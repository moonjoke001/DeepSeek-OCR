# DeepSeek-OCR 项目指南

## 项目概述
基于 vLLM 的 DeepSeek-OCR 离线部署方案，支持本地 RTX 5090 和远程 H100 服务器。

## 技术栈
- **推理引擎**: vLLM (nightly build)
- **模型**: DeepSeek-OCR (deepseek-ai/DeepSeek-OCR)
- **后端**: FastAPI + Uvicorn
- **前端**: 静态 HTML (index_fixed.html)
- **容器化**: Docker + Docker Compose

## 项目结构
```
DeepSeek-OCR/
├── docker-compose.yml          # 本地 5090 配置
├── docker-compose.h100.yml     # H100 服务器配置
├── Dockerfile.vllm             # vLLM 后端镜像
├── Dockerfile.webui            # Web UI 镜像
├── models/                     # 模型文件 (约 7-8GB)
├── workspace/                  # 工作区目录
└── web-ui/
    ├── backend/main.py         # FastAPI 后端
    └── frontend/               # 前端页面
```

## 服务端口
- **vLLM API**: 8000
- **Web UI**: 8002

## Docker 命令
```bash
# 启动
docker compose up -d

# 停止
docker compose down

# 查看日志
docker compose logs -f

# H100 服务器
docker compose -f docker-compose.h100.yml up -d
```

## API 端点
- 健康检查: `GET /api/health`
- 模型状态: `GET /api/model/status`
- 上传文件: `POST /api/upload`
- 启动 OCR: `POST /api/ocr`
- 获取结果: `GET /api/result/{task_id}`
- WebSocket: `WS /ws/{task_id}`

## 常用提示词
- 基础 OCR: `<image>\nFree OCR.`
- 文档转 Markdown: `<image>\nOCR and format as Markdown with # headings, **bold**, and numbered lists.`
- 表格识别: `<image>\n<|grounding|>OCR this image.`

## 表格渲染规范（SIT性能测试表）

### 表头结构（2行表头）
```
第1行: | 并发数(rowspan=2) | 版本(rowspan=2) | 服务接口(rowspan=2) | 性能指标(colspan=7) |
第2行: |                   |                 |                     | 请求总数 | 平均响应时间(ms) | 90%请求响应时间(ms) | 95%请求响应时间(ms) | 99%请求响应时间(ms) | 吞吐率TPS | 流量KB/S |
```

### 列定义（共10列）
| 列索引 | 列名 | X坐标范围 | 说明 |
|--------|------|-----------|------|
| 0 | 并发数 | 0-150 | 左侧分类列，有rowspan |
| 1 | 版本 | 150-240 | 版本号 V2.5 等 |
| 2 | 服务接口 | 240-420 | 接口名称，可能多行 |
| 3 | 请求总数 | 420-490 | 数值 |
| 4 | 平均响应时间 | 490-560 | 数值(ms) |
| 5 | 90%响应时间 | 560-650 | 数值(ms) |
| 6 | 95%响应时间 | 650-740 | 数值(ms) |
| 7 | 99%响应时间 | 740-830 | 数值(ms) |
| 8 | 吞吐率TPS | 830-910 | 数值 |
| 9 | 流量KB/S | 910-1000 | 数值 |

### 渲染规则
1. 表头固定2行，第1行前3列rowspan=2，第4列colspan=7显示"性能指标"
2. 数据行：并发数列检测rowspan（同一服务接口的多个并发数合并）
3. 服务接口列：多行文本合并到一个单元格
4. 数值列右对齐
5. 根据X坐标范围判断元素属于哪一列

### 智能列检测规则
由于 OCR 返回的列数不固定，需要智能检测每个单元格的类型：
- **并发数**: 包含"并发"关键词（如 "1并发", "5并发"）
- **版本**: 格式为 V + 数字（如 "V2.5"）
- **服务接口**: 中文文本（非数字、非版本号、不含"并发"）
- **数值列**: 纯数字格式

### 表格样式规范
- **边框**: 黑色 1px 实线 (`#000000`)
- **表格外边框**: 黑色 2px 实线
- **文字颜色**: 黑色 (`#000000`)
- **单元格背景**: 白色 (`#ffffff`)
- **表头背景**: 白色 (`#ffffff`)
- **性能指标表头**: 浅灰色 (`#f5f5f5`)
- **hover 效果**: 浅灰色 (`#f0f0f0`)

## 基础 OCR 模式功能规范

> 以专业的前端工程师和网页设计师的角度设计开发

### 按钮显示规则
- **基础 OCR 模式 (free)**: 只显示 **预览** 和 **下载** 按钮，不显示表格预览和复制表格按钮
- **表格识别模式 (table)**: 显示 **表格预览** 和 **复制表格** 按钮

### 结果区域按钮
- 识别结果区域显示两个按钮：**预览** 和 **下载**

### 单文件识别
- 预览区域右上角添加 **复制图标**（使用 SVG 图标，非按钮样式）
- 点击复制图标，复制当前识别结果的纯文本内容到剪贴板
- 复制成功后图标短暂变为 ✓ 状态

### 多文件识别
- **左右箭头**放置在预览区域的**左右两侧**（悬浮样式），而非左上角
- 箭头使用半透明圆形背景，hover 时高亮
- 预览区域右上角显示 **复制图标** + **文件索引**（如 "1/5"）
- 点击复制图标，复制**当前预览的文件**的识别结果内容
- 箭头切换时，预览内容和复制内容同步更新

### UI 布局规范
```
┌─────────────────────────────────────────────┐
│ 识别结果                    [预览] [下载]   │
├─────────────────────────────────────────────┤
│                         1/5  [📋]           │  ← 右上角：索引 + 复制图标
├─────────────────────────────────────────────┤
│                                             │
│  [◀]       识别结果预览内容           [▶]   │  ← 箭头在预览区左右两侧
│                                             │
└─────────────────────────────────────────────┘
```

### 设计细节
- 复制图标：使用 SVG clipboard 图标，24x24px，hover 时颜色加深
- 左右箭头：40x40px 圆形，背景 rgba(0,0,0,0.3)，hover 时 rgba(0,0,0,0.6)
- 箭头位置：垂直居中，距离边缘 12px
- 单文件时隐藏左右箭头，只显示复制图标

## 文件列表与进度整合 UI 规范

> 适用于所有 5 种模式（基础 OCR、Markdown、表格识别、图表解析、自定义）

### 设计理念
将独立的"处理进度"卡片与文件列表区域合并，减少视觉层级，提升信息密度。

### UI 布局
```
┌─────────────────────────────────────────────────────────────┐
│ 文件列表  2 个文件 · 2 已完成                 展开/收起  清空 │
├─────────────────────────────────────────────────────────────┤
│ [🖼️ 1.png ✓] [🖼️ 2.png ✓]                                  │
├─────────────────────────────────────────────────────────────┤
│ [●●●●●●●●●●] 100%                                           │  ← 内嵌进度条
├─────────────────────────────────────────────────────────────┤
│              [✅ 识别完成]  或  [🔄 重新识别]                 │  ← 动态按钮
└─────────────────────────────────────────────────────────────┘
```

### 文件列表头部
- 格式: `文件列表 N 个文件 · M 已完成 · K 待处理`
- 全部完成时省略"待处理"显示

### 按钮状态变化
| 状态 | 按钮文本 | 样式 | 可点击 |
|------|----------|------|--------|
| 无文件 | 选择文件后开始识别 | 紫色渐变 (禁用) | ✗ |
| 待识别 | 开始批量识别 (N 个文件) | 紫色渐变 | ✓ |
| 识别中 | 识别中... (M/N) | 紫色渐变 + 脉冲动画 | ✗ |
| 已完成 | ✅ 识别完成 | 绿色背景 | ✓ (重新识别) |
| 部分完成 | 继续识别 (K 个待处理) | 紫色渐变 | ✓ |

### CSS 类名
- `.btn-state-idle`: 默认紫色渐变
- `.btn-state-processing`: 紫色渐变 + 脉冲动画
- `.btn-state-completed`: 绿色背景 (#28a745)
- `.inline-progress`: 内嵌进度条容器

### 进度条样式
- 高度: 8px
- 背景: `var(--gray-200)`
- 填充: 紫色渐变 `linear-gradient(90deg, var(--primary), var(--primary-dark))`
- 圆角: 4px
